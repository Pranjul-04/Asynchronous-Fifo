# Asynchronous FIFO with Asymmetric Read/Write Width

An asynchronous (dual-clock) FIFO written in Verilog, built using **Quartus Prime** and simulated using **ModelSim**. It follows the classic Cummings-style Gray-code pointer / dual-flop synchronizer approach for safe clock domain crossing (CDC), extended to support **asymmetric data widths** — an 8-bit write port and a 32-bit read port (4:1 packing ratio).

## Features

- Dual-clock, dual-reset asynchronous FIFO (independent `wclk`/`wrst_n` and `rclk`/`rrst_n` domains)
- Asymmetric port widths: 8-bit writes, 32-bit reads (parameterizable ratio)
- Gray-coded read/write pointers with 2-flop synchronizers for safe CDC
- Coarse (grouped) pointer comparison on the write side to correctly track fullness across the width ratio
- `$clog2`-based parameterized address widths — no hard-coded bit widths
- Self-checking testbench with clock jitter, back-to-back bursts, concurrent read/write stress, and randomized stutter testing

## Architecture

```
   Write Clock Domain                          Read Clock Domain
  ┌──────────────────┐                        ┌──────────────────┐
  │   wptr_full       │──wptr (gray)──▶ sync_w2r ──▶ (into read domain)
  │  (write pointer,  │                        │   rptr_empty      │
  │   wfull flag)     │◀── rq2_wptr ──sync_w2r─┤  (read pointer,   │
  │                    │                        │   rempty flag)    │
  └─────────┬──────────┘                        └─────────┬────────┘
            │ waddr                                        │ raddr
            ▼                                              ▼
        ┌─────────────────────────────────────────────────────┐
        │                     fifo_mem                         │
        │   8-bit write port  ──▶  memory array  ──▶ 32-bit read port │
        └─────────────────────────────────────────────────────┘

  rptr (gray) ──▶ sync_r2w ──▶ (into write domain, used by wptr_full)
```

The write and read pointers are generated in their own clock domains, Gray-coded, and passed through 2-flop synchronizers before being used to compute `wfull`/`rempty` in the *other* domain. This is the standard technique for safely crossing multi-bit signals between asynchronous clocks.

## Module Details

### `asynchronous_fifo` (top-level)
Instantiates and wires together the memory, both pointer/flag modules, and both synchronizers. Computes `RATIO = RDSIZE/WDSIZE` and a reduced read-side address width `R_ASIZE` to account for the packing ratio.

### `fifo_mem`
A byte-addressable memory array (`WDSIZE`-wide words) written one `WDSIZE` chunk at a time on `wclk`. On the read side, `RATIO` consecutive write-side words are packed together combinationally into a single `RDSIZE`-wide output word — e.g. 4 bytes become one 32-bit word.

### `wptr_full`
Maintains a binary write pointer (`wbin`) and its Gray-coded form (`wptr`), advancing on `winc` while not full. To compare against the (narrower) read pointer domain, the synchronized read pointer is converted back to binary and left-shifted (`{wq2_rptr_bin, {RSHIFT{1'b0}}}`) so both pointers represent the same underlying byte address space before the full comparison `(wbinnext - wq2_rptr_bin_full) >= DEPTH`.

### `rptr_empty`
Maintains a binary read pointer (`rbin`) and Gray-coded form (`rptr`) in units of `RDSIZE`-wide words, advancing on `rinc` while not empty. `raddr` is derived by shifting `rbin` left by `RSHIFT = $clog2(RATIO)` bits to translate a read-word index back into a byte address for `fifo_mem`. Emptiness is determined by comparing the synchronized write pointer (scaled to the same shifted address space) against the next read pointer.

### `sync_r2w` / `sync_w2r`
Standard 2-flop synchronizers that resample a Gray-coded pointer from one clock domain into the other, one flip-flop stage at a time, to reduce the probability of metastability propagating into logic.

### `gray2bin`
A shared combinational utility that converts a Gray-coded pointer back to binary via a bit-by-bit XOR chain, used by both `wptr_full` and `rptr_empty` to interpret the synchronized pointer from the opposite domain.

## Handling Asymmetric Widths

Because the write port (8 bits) and read port (32 bits) operate at different granularities, the design cannot simply share one pointer width across both domains:

- The write pointer counts in units of single bytes (`WDSIZE`-wide words) and has address width `ASIZE`.
- The read pointer counts in units of packed 32-bit words and has a *reduced* address width `R_ASIZE = $clog2(DEPTH / RATIO)`.
- Whenever a pointer crosses into the other domain, it's re-scaled: the read pointer is left-shifted by `$clog2(RATIO)` bits before being compared against the write pointer (and vice versa), so both sides are always comparing pointers in the same byte-addressed space.

This coarse/grouped pointer approach avoids needing non-power-of-2 arithmetic or bit-shift tricks that only work cleanly for power-of-2 ratios — the design assumes `RDSIZE/WDSIZE` is an integer ratio (here, 4).

## Clock Domain Crossing Strategy

1. Pointers are always Gray-coded before crossing domains — only a single bit changes between consecutive values, which prevents multi-bit sampling errors during a clock domain crossing.
2. Each crossing pointer passes through **two** flip-flop stages (`wq1_rptr`/`wq2_rptr` and `rq1_wptr`/`rq2_wptr`) in the destination clock domain before being used, giving metastability time to resolve.
3. Full/empty flags are computed **only** using the synchronized (safe) version of the opposite pointer — never the raw pointer directly from the other clock domain.

## Parameters

| Parameter | Default | Description |
|---|---|---|
| `WDSIZE` | 8 | Write port data width (bits) |
| `RDSIZE` | 32 | Read port data width (bits) |
| `ASIZE` | 4 | Write-side address width (FIFO depth = `2^ASIZE` write-words) |
| `AE_level` | 4 | Almost-empty threshold |
| `AF_level` | 12 | Almost-full threshold |
| `RATIO` (local) | `RDSIZE/WDSIZE` = 4 | Read/write width ratio |
| `DEPTH` (local) | `2^ASIZE` = 16 | FIFO depth in write-words |

## Testbench Scenarios

The testbench (`tb_asynchronous_fifo`) generates independent, jittered write and read clocks (`wclk` ~3 ns period + random jitter, `rclk` ~5 ns period + random jitter) to stress the CDC logic under realistic, non-aligned clock edges. Test data is generated at runtime (`(i * 11) & 0xFF` pattern), written to `burst_data.hex`, and reloaded via `$readmemh` so both the write and read sides can independently compute expected values.

1. **Reset** – asserts both resets, then releases `wrst_n`/`rrst_n` on their respective clock domains
2. **Sequential blast** – fills the FIFO to full depth, then drains it, checking every packed 32-bit word against the expected value assembled from 4 consecutive bytes
3. **Controlled concurrent stress** – writes and reads run concurrently (`fork...join`), with the read side starting after a short delay, to test simultaneous access from both domains
4. **Randomized jitter stress** – both write and read run concurrently across the full test data set, with random stalls (~20% chance of a multi-cycle write pause, ~30% chance of a multi-cycle read pause) to exercise the full/empty logic under bursty, unpredictable traffic
5. **Final check** – confirms zero data mismatches and that all bytes were fully written and read; a simulation timeout watchdog guards against hangs

## Getting Started

1. Open **Quartus Prime** and create a new project (or open the existing `.qpf`).
2. Add all Verilog source files: `asynchronous_fifo.v`, `sync_r2w.v`, `sync_w2r.v`, `fifo_mem.v`, `rptr_empty.v`, `wptr_full.v`, `gray2bin.v`.
3. Set `asynchronous_fifo` as the top-level entity for synthesis.
4. In Quartus, go to **Tools → Options → EDA Tool Options** and point it to your ModelSim installation, then set ModelSim as the simulation tool under **Assignments → Settings → EDA Tool Settings → Simulation**.
5. Launch ModelSim from Quartus (**Tools → Run Simulation Tool → RTL Simulation**), or open ModelSim directly and compile all source files plus `tb_asynchronous_fifo.v`.
6. Run the simulation (`run -all` in the ModelSim console). The testbench generates its own `burst_data.hex` on the fly, so no external test-vector file is needed beforehand.
7. Check the transcript for per-word `ERROR!` messages and the final `TEST PASSED` / `TEST FAILED` summary.

## Known Limitations

- Assumes `RDSIZE/WDSIZE` is an exact integer ratio; non-power-of-2 or non-integer ratios are not supported by the current addressing scheme.
- `almost_empty`/`almost_full` outputs are computed but left unconnected at the top level — no ports currently expose them.
- No support for simultaneous write when full or read when empty beyond simple gating (`wclken && !wfull`, `rinc & ~rempty`) — attempted over/underflows are simply ignored rather than flagged as errors.
